C# Interview Questions

A reference sheet covering .NET fundamentals, OOP concepts, collections, delegates, and core language keywords — organized for quick review before an interview.

What is .NET?

Ans. .NET is a software framework from Microsoft for developing applications on Windows. It is similar to other software development frameworks like Java Platform, Enterprise Edition (J2EE), and comprises ASP.NET, languages such as C#, VB.NET, COBOL, Perl, etc.

What is CLR?

Ans. CLR refers to Common Language Run-time. It is an essential component of the .NET framework and can be used as a building block of various applications. An essential feature of CLR is that it ensures a secure execution environment for applications.

What is CLS?

Ans. CLS refers to Common Language Specification. It allows users to use inter-language compatible components and helps to reuse the code in other .NET compatible languages.

IEnumerable

  1. IEnumerable exists in the System.Collections namespace.
  2. IEnumerable is suitable for querying data from in-memory collections like List, Array, and so on.
  3. While querying data from the database, IEnumerable executes a "select query" on the server-side, loads data in-memory on the client-side, and then filters the data.

IQueryable

  1. IQueryable exists in the System.Linq namespace.
  2. IQueryable is suitable for querying data from out-of-memory (like remote database, service) collections.
  3. While querying data from a database, IQueryable executes a "select query" on the server-side with all filters applied.

Task & Thread

In C#, the core difference is that a Thread represents an actual operating system-level execution thread, while a Task is a high-level abstraction representing an asynchronous operation.

Interface and Abstract Class

Interfaces have all the methods having only declaration but no definition. In an abstract class, we can have some concrete methods. In an interface, all the methods are public. An abstract class may have private methods.

Abstract Class

A class with the abstract modifier indicates that the class is an abstract class. An abstract class cannot be instantiated. The purpose of an abstract class is to provide a common definition of a base class that multiple derived classes can share.

Characteristics of Abstract Class

  1. An abstract class cannot be instantiated.
  2. An abstract class can have a constructor, but you cannot create an object directly from the abstract class; the constructor is called automatically by the subclass's constructor (using super()) to initialize the inherited state.
  3. An abstract class can implement an interface.
  4. An abstract class can contain abstract methods and properties.
  5. It is not possible to modify an abstract class with the sealed modifier because the two modifiers have opposite meanings. The sealed modifier prevents a class from being inherited, and the abstract modifier requires a class to be inherited.
  6. A non-abstract class derived from an abstract class must include actual implementations of all inherited abstract methods and accessors.

Interface

An interface is an abstract class which has only public abstract methods, and the methods only have the declaration, not the definition. These abstract methods must be implemented in the inherited classes.

Partial Class

The partial keyword indicates that other parts of the class, struct, or interface can be defined in the namespace. All the parts must use the partial keyword. All the parts must be available at compile time to form the final type. All the parts must have the same accessibility, such as public, private, and so on.

Characteristics of Partial Class

  1. All the partial class definitions must be in the same assembly and namespace.
  2. All the parts must have the same accessibility, like public or private, etc.
  3. If any part is declared abstract, sealed, or a base type, then the whole class is declared of the same type.
  4. Different parts can have different base types, and so the final class will inherit all the base types.
  5. The partial modifier can only appear immediately before the keywords class, struct, or interface.
  6. Nested partial types are allowed.

Static Class

A class with the static keyword that contains only static members is defined as a static class. A static class cannot be instantiated.

Characteristics of Static Class

  1. A static class cannot be instantiated using a new keyword.
  2. Static items can only access other static items. For example, a static class can only contain static members, e.g., variables, methods, etc.
  3. A static method can only contain static variables and can only access other static items.
  4. Static items share resources between multiple users.
  5. Static cannot be used with indexers, destructors, or types other than classes.
  6. A static constructor in a non-static class runs only once, when the class is instantiated for the first time.
  7. A static constructor in a static class runs only once, when any of its static members are accessed for the first time.
  8. Static members are allocated in a high frequency heap area of the memory.

Sealed Class

A sealed class is a class that cannot be inherited and is used to restrict the properties.

Key points:

  • A sealed class is created using the sealed keyword.
  • Access modifiers are not applied to a sealed class.
  • To access the sealed members, we must create an object of the class.

Constructor in C#

A special method of the class that is automatically invoked when an instance of the class is created is called a constructor. The main use of constructors is to initialize the private fields of the class while creating an instance for the class. When you have not created a constructor in the class, the compiler will automatically create a default constructor for the class. The default constructor initializes all numeric fields in the class to zero, and all string and object fields to null.

Key Points Regarding Constructors

  • A class can have any number of constructors.
  • A constructor doesn't have any return type, not even void.
  • A static constructor cannot be a parameterized constructor.
  • Within a class, you can create only one static constructor.

Types of Constructors

1. Default Constructor

  • Definition: A parameterless constructor provided by the compiler if no explicit constructor is defined.
  • Function: Initializes fields to their default values (e.g., 0 for numeric types, null for reference types).

2. Parameterized Constructor

  • Definition: A constructor that takes one or more arguments.
  • Function: Allows you to initialize an object with specific, custom values during creation.

3. Static Constructor

  • Definition: Defined with the static keyword; it takes no access modifiers or parameters.
  • Behavior: Automatically called only once by the runtime, before any static members are accessed or the first instance is created.

4. Private Constructor

  • Definition: Uses the private access modifier to prevent external instantiation of the class.
  • Use Case: Commonly used in the Singleton Design Pattern or for utility classes containing only static members.

5. Copy Constructor

  • Definition: A parameterized constructor that takes an object of the same class as a parameter.
  • Function: Creates a new object by copying the data members of an existing instance.

Garbage Collection

Automatic memory management is made possible by garbage collection in the .NET Framework. When a class object is created at runtime, a certain memory space is allocated to it in the heap memory. However, once all the actions related to the object are completed in the program, the memory space allocated to it becomes waste, as it cannot be used. Garbage collection is very useful here, as it automatically releases the memory space once it is no longer required.

Dispose

  • In C#, the IDisposable interface includes the Dispose() method — a method for releasing unmanaged resources, like file handles, database connections, or network connections.
  • When an object is no longer needed, or the developer desires to release the resources associated with it, it is their responsibility to explicitly call the Dispose() method.
  • The using statement and the Dispose() method are usually used together to guarantee that resources are released on time.

Finalize

  • The garbage collector calls the Finalize() method, a member of the Object class, prior to recovering memory that an object that is no longer accessible had taken up.
  • During the garbage collection process, it is used to clean up mismanaged resources.
  • Because garbage collection is not deterministic, relying solely on the Finalize() method for resource cleanup may cause resources to be released later than intended.

out & ref

The out keyword in C# is used for passing arguments to methods as a reference type. It is generally used when a method returns multiple values. The out parameter does not pass the property.

The ref keyword in C# is used for passing arguments by reference. In other words, any changes made to the argument inside the method will reflect in that variable when control returns to the calling method. The ref parameter also does not pass the property.

Extension Method

In C#, the extension method concept allows you to add new methods to an existing class or structure without modifying the source code of the original type. No special permission is needed from the original type, and there is no need to re-compile it. Extension methods were introduced in C# 3.0.

  1. It is a static method.
  2. It must be located in a static class.
  3. It uses the this keyword as the first parameter with a type in .NET, and this method is called by a given type instance on the client side.
  4. It is shown by Visual Studio IntelliSense — when you press the dot (.) after a type instance, it appears in IntelliSense.
  5. An extension method should be in the same namespace as it is used, or you need to import the namespace of the class with a using statement.
  6. You can give any name to the class that has an extension method, but the class must be static.
  7. If you want to add new methods to a type and don't have its source code, the solution is to implement extension methods for that type.
  8. If you create an extension method with the same signature as a method on the type you're extending, the extension method will never be called.
public static class XX
{
    public static void ToStringOrNULL(this String ob)
    {
        Console.WriteLine("Hello I m extended method");
    }
}

Generic Class & Method

Generics allow you to design classes and methods that work with any data type while providing type safety, code reusability, and performance benefits. A type parameter, conventionally named T, acts as a placeholder for the actual data type, which is specified at compile time.

Generic Class

A generic class defines a template where one or more types are specified as parameters when an instance of the class is created. This is widely used in built-in collections like List<T> and Dictionary<TKey, TValue>.

public class GenericClass<T>
{
    public T Data { get; set; }

    public GenericClass(T data)
    {
        Data = data;
    }

    public void DisplayData()
    {
        Console.WriteLine($"The value is: {Data}");
    }
}

OOPS

Abstraction

Abstraction is "to represent the essential feature without representing the background details." Abstraction lets you focus on what the object does instead of how it does it. It involves designing classes that represent essential features while hiding the complex underlying logic, achieved using abstract classes or interfaces.

Encapsulation

Wrapping up a data member and a method together into a single unit (i.e., a class) is called encapsulation. It is achieved using access modifiers (like private, public, protected) and properties, to protect the internal data of an object from unauthorized external access. This allows for data hiding and ensures data integrity through controlled access.

Polymorphism

The word polymorphism means having many forms. In the object-oriented programming paradigm, polymorphism is often expressed as "one interface, multiple functions." Polymorphism can be static or dynamic. In static polymorphism, the response to a function is determined at compile time. In dynamic polymorphism, it is decided at run time.

Static Polymorphism

The mechanism of linking a function with an object during compile time is called early binding, also called static binding. C# provides two techniques to implement static polymorphism:

  • Function overloading
  • Operator overloading

Dynamic Polymorphism

C# allows you to create abstract classes that provide partial class implementation of an interface. Implementation is completed when a derived class inherits from it. Abstract classes contain abstract methods, which are implemented by the derived class, and the derived classes have more specialized functionality.

Rules about abstract classes:

  • You cannot create an instance of an abstract class.
  • You cannot declare an abstract method outside an abstract class.
  • When a class is declared sealed, it cannot be inherited; abstract classes cannot be declared sealed.

Function Overloading

You can have multiple definitions for the same function name in the same scope. The definitions must differ from each other by the types and/or the number of arguments in the argument list. You cannot overload function declarations that differ only by return type.

Overriding

Overriding is a feature that allows a subclass or child class to provide a specific implementation of a method already provided by one of its super-classes or parent classes. When a method in a subclass has the same name, parameters (signature), and return type (or sub-type) as a method in its super-class, the method in the subclass is said to override the method in the super-class. Method overriding is one of the ways C# achieves run-time polymorphism (dynamic polymorphism).

Delegates

A delegate in C# is a type-safe function pointer — an object that holds a reference to a method. This allows methods to be treated as variables, passed as parameters to other methods, and executed at runtime without the calling code needing to know the specific method being invoked. Delegates are the foundation of events and callbacks in C#.

  • Singlecast delegate: Points to a single method at a time. The delegate is assigned to a single method at a time. Derived from the System.Delegate class.
  • Multicast delegate: When a delegate is wrapped with more than one method, that is known as a multicast delegate.
using System;
using System.Collections.Generic;

public delegate bool IsEligibleForPromotion(Employee emp);

public class Employee
{
    public int ID { get; set; }
    public string Name { get; set; }
    public decimal Salary { get; set; }
    public float Experience { get; set; }

    public static void PromoteEmployees(List<Employee> employeeList,
        IsEligibleForPromotion criteria)
    {
        Console.WriteLine($"\n--- Checking promotions based on custom criteria ---");
        foreach (Employee emp in employeeList)
        {
            if (criteria(emp))
            {
                Console.WriteLine($"{emp.Name} has been promoted!");
            }
        }
    }
}

class Program
{
    static void Main()
    {
        List<Employee> employees = new List<Employee>
        {
            new Employee { ID = 101, Name = "Ravi", Salary = 20000, Experience = 3 },
            new Employee { ID = 102, Name = "John", Salary = 30000, Experience = 5 },
            new Employee { ID = 103, Name = "Mary", Salary = 50000, Experience = 8 },
            new Employee { ID = 104, Name = "Mike", Salary = 10000, Experience = 2 }
        };

        bool PromoteByExperience(Employee emp) => emp.Experience >= 5;
        bool PromoteBySalary(Employee emp) => emp.Salary >= 30000;

        IsEligibleForPromotion experienceCriteria = PromoteByExperience;
        Employee.PromoteEmployees(employees, experienceCriteria);

        IsEligibleForPromotion salaryCriteria = PromoteBySalary;
        Employee.PromoteEmployees(employees, salaryCriteria);
    }
}

Collections

Collection classes are specialized classes for data storage and retrieval. These classes provide support for stacks, queues, lists, and hash tables. Most collection classes implement the same interfaces.

Collection classes serve various purposes, such as allocating memory dynamically to elements and accessing a list of items on the basis of an index, etc. These classes create collections of objects of the Object class, which is the base class for all data types in C#.

Generics

Generics is a technique that enriches your programs in the following ways:

  • It helps you maximize code reuse, type safety, and performance.
  • You can create generic collection classes. The .NET Framework class library contains several generic collection classes in the System.Collections.Generic namespace. You may use these instead of the collection classes in the System.Collections namespace.
  • You can create your own generic interfaces, classes, methods, events, and delegates.
  • You may create generic classes constrained to enable access to methods on particular data types.

Boxing and Unboxing

Boxing and unboxing is an important concept in C#. The C# type system contains three data types: value types (int, char, etc.), reference types (object), and pointer types. Boxing and unboxing convert a value type to a reference type, and vice versa, enabling a unified view of the type system in which a value of any type can be treated as an object.

  • The process of converting a value type (char, int, etc.) to a reference type (object) is called boxing.
  • Boxing is an implicit conversion process in which the object type (super type) is used.
  • The value type is always stored on the stack. The referenced type is stored on the heap.
int num = 23;      // 23 is assigned to num
object Obj = num;  // Boxing

Generic Collection

Generic collections are significantly faster than non-generic collections in C#, primarily because they avoid the performance-intensive processes of boxing and unboxing value types.

Why Generics Are Faster

  • Elimination of boxing/unboxing: Non-generic collections (like ArrayList or Hashtable) store all elements as the object type. Adding a value type (like int or a struct) requires it to be "boxed" (converted to an object and stored on the heap); retrieving it requires "unboxing" it back to its original value type. These operations add significant overhead in both execution time and memory allocation.
  • Memory efficiency: Generic collections (like List<int>) use a strongly-typed internal array (e.g., int[]). Value types are stored contiguously in memory without the extra overhead of individual object headers and references, leading to better cache performance and less pressure on the garbage collector.
  • No runtime type checking for value types: For generic collections, the compiler knows the exact type of elements at compile time, eliminating the need for runtime type checks and explicit casting when retrieving items.
  • Optimized implementation: The generic collection classes in the .NET Framework were designed with modern performance optimizations that were not applied to the older, non-generic counterparts.

Access Modifier

The public keyword is an access modifier, used to set the access level / visibility for classes, fields, methods, and properties.

C# has the following access modifiers:

  • public: Accessible from anywhere in the program, within the same assembly or another assembly. It is the most permissive access level.
  • private: Accessible only within the same class or struct where it is declared. This is the default access modifier for class members if none is specified.
  • protected: Accessible within the class where it is declared and by any class that derives from it (child classes), even if the derived class is in a different assembly.
  • internal: Accessible only within the same assembly (project), but not from other assemblies. This is the default access modifier for top-level classes and structs.
  • protected internal: Accessible within the same assembly, or by any class derived from the containing class, even in another assembly. A combination of protected and internal access.
  • private protected: Accessible only within the containing class or derived classes within the same assembly. Available from C# 7.2 onward.
