Feature of .Net Core 8

NET 8 is a Long-Term Support (LTS) release of the cross-platform, open-source framework, focusing heavily on performance, cloud-native development, and full-stack web UI. 

Key features include:

Performance & Cloud-Native 

  • Performance Enhancements: Thousands of improvements in performance, stability, and security, including up to 20% performance gains from Dynamic Profile-Guided Optimization (PGO).

  • .NET Aspire: An opinionated stack of NuGet packages for building resilient, observable, and configurable cloud-native applications, which simplifies orchestration, components, and tooling.

  • Native Ahead-of-Time (AOT) Compilation: Enhanced support for AOT, which compiles apps into native code, resulting in smaller deployment sizes, faster startup times, and reduced memory usage.

  • Garbage Collection Improvements: The garbage collector now features dynamic adaptation to application sizes (DATAS) for more efficient memory management, especially in containerized environments. 

C# 12 & AI

  • C# 12 Integration: Includes new language features such as primary constructors for any class or struct, default values for parameters in lambda expressions, and enhanced using directives for aliasing any type.

  • AI & Machine Learning Support: Seamless integration with large language models (LLMs) like OpenAI's GPT and enhanced System.Numeric libraries to facilitate AI-infused .NET applications. 

Web & Client Development (ASP.NET Core & Blazor) 

  • Unified Blazor: Blazor is now a full-stack web UI framework, allowing components to run on both the server and client (WebAssembly) in the same app. This includes support for static server-side rendering (SSR), streaming rendering, and enhanced navigation/form handling.

  • .NET MAUI Enhancements: Improved performance, reliability, and developer experience for cross-platform mobile and desktop applications, including a new Visual Studio Code extension.

  • Minimal API Improvements: Enhanced support for form binding and API authoring capabilities, including the use of .http files in project templates for easier API testing. 

Data Access & Tools

  • Entity Framework (EF) Core 8: Support for complex types as value objects, lazy loading of no-tracking queries, and enhanced JSON column mapping for relational databases.

  • System.Text.Json Improvements: Performance boosts and support for new naming policies like snake_case and kebab-case, with better handling of serialization from interface hierarchies.

  • DevOps and Observability: Better integration with CI/CD tools, built-in support for OpenTelemetry for distributed tracing, and advanced metrics collection. 

.Net Framewor & .Net Core

The primary difference is that .NET Framework is a legacy, Windows-only platform, while .NET (formerly .NET Core) is a modern, cross-platform, open-source framework designed for high performance and cloud-based applications. 

Microsoft has ceased feature development on the .NET Framework (the final version is 4.8) and recommends using the unified .NET platform for all new development. 

Key Differences: .NET Framework vs. .NET (Core)

Aspect  .NET Framework .NET (Core)
Platform Windows only Cross-platform (Windows, macOS, Linux)
Source Mostly closed source (proprietary) Open source with community contributions
Performance Slower performance and scalability High performance and scalable, optimized for modern apps
Architecture Monolithic architecture, single installation per machine Modular (uses NuGet packages), supports side-by-side versions
Deployment Requires specific Windows server setup (IIS) Flexible, supports self-contained, Docker containers, and cloud deployment

What is the ASP.NET Core?

ASP.NET Core is not an upgraded version of ASP.NET. ASP.NET Core is completely rewriting that work with the .net Core framework. It is much faster, configurable, modular, scalable, extensible, and has cross-platform support. It can work with both .NET Core and .net framework via the .NET standard framework. It is best suitable for developing cloud-based such as web applications, mobile applications, and IoT applications.

ASP.NET Core was primarily designed to make the most important part of the ASP.NET components under the concept learn and the compose framework where the previous ASP.NET  components were released under a variety of different licenses periodically, The ASP.NET Core framework is a completely open-sourced framework.

What are the features provided by ASP.NET Core?.

Following are the core features that are provided by the ASP.NET Core

  • Built-in supports forDependency Injection

  • Built-in supports for the logging framework and it can be extensible

  • Introduced a new, fast and cross-platform web server - Kestrel. So, a web application can run without IIS, Apache, and Nginx.

  • Multiple hosting ways are supported

  • It supports modularity, so the developer needs to include the module required by the application. However, the .NET Core framework is also providing the meta package that includes the libraries

  • Command-line supports to creating, building, and running of the application

  • There is no web.config file. We can store the custom configuration into an appsettings.json file

  • There is no Global.asax file. We can now register and use the services in the startup class

  • It has good support for asynchronous programming

What are the advantages of ASP.NET Core over ASP.NET?

There are the following advantages of ASP.NET Core over ASP.NET :

  • It is cross-platform, so it can be run on Windows, Linux, and Mac.

  • There is no dependency on framework installation because all the required dependencies are shipped with our application

  • ASP.NET Core can handle more requests than the ASP.NET

  • Multiple deployment options available withASP.NET Core

What are Metapackages?

The framework .NET Core 2.0 introduced Metapackage which includes all the supported packages by ASP.NET code with their dependencies into one package. It helps us to do fast development as we don't require to include the individual ASP.NET Core packages. The assembly Microsoft.AspNetCore.All is a meta package provided by ASP.NET core.

Can ASP.NET Core application work with full .NET 4.x Framework?

Yes. ASP.NET core application works with full .NET framework via the .NET standard library.

What is the startup class in ASP.NET core?

The startup class is the entry point of the ASP.NET Core application. Every .NET Core application must have this class. This class contains the application configuration related items. It is not necessary that the class name must be "Startup", it can be anything, we can configure the startup class in the Program class.

public class Program
{
public static void Main(string[] args)
{
CreateWebHostBuilder(args).Build().Run();
}
public static IWebHostBuilder CreateWebHostBuilder(string[] args) =>
WebHost.CreateDefaultBuilder(args)
.UseStartup<TestClass>();
}

ConfigureServices method?

This is an optional method of startup class. It can be used to configure the services that are used by the application. This method calls first when the application is requested for the first time. Using this method, we can add the services to the DI container, so services are available as a dependency in the controller constructor.

Configure method?

It defines how the application will respond to each HTTP request. We can configure the request pipeline by configuring the middleware. It accepts IApplicationBuilder as a parameter and also it has two optional parameters: IHostingEnvironment and ILoggerFactory. Using this method, we can configure built-in middleware such as routing, authentication, session, etc. as well as third-party middleware.

What is middleware?

It is software that is injected into the application pipeline to handle requests and responses. They are just like chained to each other and form as a pipeline. The incoming requests are passed through this pipeline where all middleware is configured, and middleware can perform some action on the request before passing it to the next middleware. Same as for the responses, they are also passing through the middleware but in reverse order.

Custom Middleware

Custom middleware is a component you insert into the application's request pipeline to handle specific functionalities like logging, authentication, or error handling. Each middleware component can perform tasks before and after the rest of the pipeline executes or short-circuit the pipeline entirely

public class CustomLoggingMiddleware
{
private readonly RequestDelegate _next;
public CustomLoggingMiddleware(RequestDelegate next)
{
_next = next;
}
public async Task InvokeAsync(HttpContext context)
{
// Logic to execute BEFORE the next middleware
Console.WriteLine($"Incoming request: {context.Request.Path}");
// Call the next middleware in the pipeline
await _next(context);

// Logic to execute AFTER the next middleware has finished and the response is being sent back

Console.WriteLine($"Outgoing response: {context.Response.StatusCode}");

}

}

Add an extension method

public static class CustomMiddlewareExtensions
{
public static IApplicationBuilder UseCustomLoggingMiddleware(this IApplicationBuilder builder)
{
return builder.UseMiddleware<CustomLoggingMiddleware>();
}
}
Then call the middleware in program.cs file
app.UseCustomLoggingMiddleware();

IApplicationBuilder.Use() and IApplicationBuilder.Run()?

We can use both the methods in Configure methods of the startup class. Both are used to add middleware delegates to the application request pipeline. The middleware adds using IApplicationBuilder.Use may call the next middleware in the pipeline whereas the middleware adds using IApplicationBuilder.The run method never calls the subsequent middleware. After IApplicationBuilder.Run method, system stop adding middleware in the request pipeline.

"Map" extension middleware?

It is used for branching the pipeline. It branches the ASP.NET Core pipeline based on request path matching. If the request path starts with the given path, middleware on to that branch will execute.

public void Configure(IApplicationBuilder app)
{
app.Map("/path1", Middleware1);
app.Map("/path2", Middleware2);
}

What is routing in ASP.NET Core?

Routing is functionality that map incoming request to the route handler. The route can have values (extract them from the URL) that are used to process the request. Using the route, routing can find a route handler based on the URL. All the routes are registered when the application is started. There are two types of routing supported by ASP.NET Core

  • The conventional routing

  • Attribute routing

The Routing uses routes to map incoming requests with the route handler and Generates URL that is used in response. Mostly, the application has a single collection of routes and this collection is used for the process of the request. The RouteAsync method is used to map incoming requests (that match the URL) with available in route collection.

Dependency Injection

Dependency Injection (DI) is a software design pattern where a class receives its required objects (dependencies) from an external source rather than creating them itself. In C#, it is the standard way to achieve Loose Coupling and Inversion of Control (IoC), making your code easier to maintain, test, and scale. 

Think of it this way: instead of a Car class being responsible for building its own Engine, the Engine is "injected" into the Car from the outside.

1. Why use Dependency Injection?

Using the new keyword inside a class to create dependencies creates "tight coupling." DI helps solve several problems.

  • Easier Testing: You can easily swap real services (like a database) with "mock" versions for unit testing.

  • Maintainability: If you need to change how a service is implemented, you only change it in one place (the registration) rather than every class that uses it.

  • Flexibility: It allows you to program to an interface rather than a concrete implementation. 

2. Types of Dependency Injection

There are three main ways to "inject" dependencies into a C# class:

  • Constructor Injection (Most Common): The dependency is passed through the class constructor. This is the preferred method in .NET.

csharp

public class ProductService {
private readonly IRepository _repository;
// The dependency is injected here
public ProductService(IRepository repository) {
_repository = repository;
}
}

  • Property (Setter) Injection: The dependency is assigned to a public property. This is useful for optional dependencies.

  • Method Injection: The dependency is passed directly into a specific method as a parameter. 

3. Service Lifetimes in .NET 

When you register a service in the built-in .NET DI container, you must decide its "lifetime." According to GeeksforGeeks' guide on DI, there are three primary scopes: 

Lifetime  Description
Transient Created every time they are requested from the service container.
Scoped Created once per client request (e.g., once per HTTP request in ASP.NET Core).
Singleton Created once the first time they are requested; every subsequent request uses the same instance.

4. Implementation Steps

To implement DI in a modern .NET application (like ASP.NET Core), you typically follow these steps:

  1. Define an Interface: Create an interface (e.g., IMessageService) for your dependency.

  2. Create an Implementation: Write the concrete class that implements that interface.

  3. Register the Service: In your Program.cs file, register the interface and the implementation with the IServiceCollection.

  4. Inject the Service: Add the interface as a parameter to the constructor of the class where you want to use it. 

Singleton Transient Scopped

In .NET Core Dependency Injection, the difference between Singleton, Transient, and Scoped lies in how long the service instance lives and how it is shared across different parts of the application. 

Lifetime  Instance Creation Shared Across
Singleton Created once when first requested, and the same instance is reused for the entire application lifetime. The entire application, all requests, and all components.
Scoped

Created once per client request (e.g., an HTTP request in a web application), and that same instance is shared within that specific request's scope.

Within the same HTTP request, every component that asks for the service will receive the same shared instance. A completely new instance is created for the next request.

 The current HTTP request or manually created scope only. Different requests get different instances.
Transient A new instance is created every single time the service is requested from the dependency injection container, even within the same HTTP request. Not shared; each dependent object gets its own fresh instance.

When to Use Which

  • Singleton: Use for services that are expensive to create, need to maintain a global or application-wide state, or manage shared, static resources (like configuration settings or a memory cache).

  • Scoped: This is the most common lifetime for web applications and is ideal for services that need to maintain state during a single request but not across multiple requests. A prime example is the DbContext in Entity Framework Core, which should have one instance per request to manage data operations consistently.

  • Transient: Use for lightweight, stateless services where each use needs an independent instance to avoid concurrency issues or side effects. Simple utility or notification services are good candidates for transient lifetime.

Async Await Task

async and await keywords and the Task type simplify asynchronous programming by allowing non-blocking operations to be written in a way that reads like synchronous code. This improves application responsiveness, especially for I/O-bound tasks like network requests, database queries, or file access. 

Key Concepts

  • Task and Task<T>: The objects represent an ongoing asynchronous operation. A Task is used for methods that do not return a value (similar to void), while Task<T> is used for methods that return a result of type T.

  • async Keyword: async modifier is used in a method signature to indicate that the method can contain await expressions. It tells the compiler to generate a state machine to manage the asynchronous execution.

  • await Keyword: When the await operator is applied to a Task within an async method, the method suspends its execution and returns control to its caller. This frees up the current thread to perform other work. When the awaited task completes, the remainder of the method is scheduled to resume.

Exception Handling

1. IExceptionHandler

The IExceptionHandler interface requires implementing a single method, TryHandleAsync. It allows you to create focused handlers for specific error types, return customized responses like standardized Problem Details (RFC 7807), and short-circuit the pipeline. [1, 2, 3]

Step 1: Create the Handler Class [1, 2]

csharp

using

Use code with caution.

csharp

Microsoft.AspNetCore.Diagnostics

Use code with caution.

csharp

;

using Microsoft.AspNetCore.Mvc;
public class GlobalExceptionHandler : IExceptionHandler
{
private readonly ILogger<GlobalExceptionHandler> _logger;
public GlobalExceptionHandler(ILogger<GlobalExceptionHandler> logger)
{
_logger = logger;
}
public async ValueTask<bool> TryHandleAsync(
HttpContext httpContext,
Exception exception,
CancellationToken cancellationToken)
{
_logger.LogError(exception, "An unhandled exception occurred: {Message}", exception.Message);
// Map specific exceptions to distinct status codes
var (statusCode, title) = exception switch
{
ArgumentException => (StatusCodes.Status400BadRequest, "Bad Request"),
KeyNotFoundException => (StatusCodes.Status404NotFound, "Resource Not Found"),
_ => (StatusCodes.Status500InternalServerError, "Internal Server Error")
};
var problemDetails = new ProblemDetails
{
Status = statusCode,
Title = title,
Detail = exception.Message,
Instance = httpContext.Request.Path
};
httpContext.Response.StatusCode = statusCode;
// Write the RFC-compliant JSON response
await httpContext.Response.WriteAsJsonAsync(problemDetails, cancellationToken);
// Return true to signal that this exception is handled
return true;
}
}
Use code with caution.
[1, 2, 3, 4]

2. Built-in Environment-Specific Behavior

ASP.NET Core templates provide built-in middleware to structure responses differently based on your host environment. [1, 2]

  • Development (UseDeveloperExceptionPage): Automatically mapped in local environments, this renders an HTML/JSON payload containing stack traces, database queries, and query string fragments. [1, 2]

  • Production (UseExceptionHandler("/error")): Hides system internals to prevent data leaks. It can re-route the internal pipeline execution to a separate endpoint (like a Minimal API route or MVC Controller) to render generic customer messages. [1, 2, 3, 4]

csharp

if (app.Environment.IsDevelopment())
{
app.UseDeveloperExceptionPage();
}
else
{
app.UseExceptionHandler("/error"); // Reroutes internal execution path safely
}
Use code with caution.

3. Alternative Approaches (Legacy & Specialized)

While IExceptionHandler is preferred for modern projects, alternative options exist based on structural constraints: [1]

Method Best For Trade-offs
Custom Middleware Legacy .NET 7 or older architectures Requires manual try/catch and direct stream modification.
