DbContext, tracking behavior, LINQ operators, and performance best practices.

DBContext

The DbContext class in Entity Framework represents the session with the database and provides a set of APIs to perform CRUD (Create, Read, Update, Delete) operations on entities. It also manages the entity objects during their lifecycle.

DB Set

A DbSet is a core class in Microsoft’s Entity Framework (EF) and EF Core that represents a collection of a specific entity type (like a table or view) in your database [1, 2, 3]. It acts as a gateway for performing CRUD (Create, Read, Update, Delete) operations and querying that data using LINQ

Data Annotation

Data annotations are broadly categorized into validation, display, and data modeling attributes. 

Validation Attributes

Common validation attributes include [Required], [StringLength], [Range], [RegularExpression], [EmailAddress], [Phone], [Url], and [Compare] for comparing property values. 

Display and Formatting Attributes

Attributes like [Display] customize the property's name in the UI, [DataType] specifies the kind of data for appropriate rendering, and [DisplayFormat] controls how data is shown and formatted. 

Data Modeling Attributes (used with Entity Framework)

Attributes for data modeling in Entity Framework include [Key] for primary keys, [Column] and [Table] to override default database naming conventions, [NotMapped] to exclude properties, and [ForeignKey] to define relationships. 

Example.

Tracking Vs No Trackinng

In Entity Framework (EF), tracking queries attach returned entities to the DbContext's change tracker, enabling automatic updates to the database when SaveChanges() is called. No-tracking queries, using the AsNoTracking() method, skip this process, offering significant performance benefits for read-only scenarios

In C# Entity Framework, "no tracking" is a query mode where the DbContext does not monitor changes to the retrieved entities, resulting in improved performance and reduced memory usage for read-only scenarios.

using (var context = new EntityModelContext())

{

var employees = context.Employees.AsNoTracking().ToList();
// Entities in the 'employees' list are not tracked.
}

Transaction

Entity Framework Core supports transactions through the SaveChanges method. Multiple changes within a single SaveChanges call are made within a transaction. Additionally, you can explicitly manage transactions using Database. BeginTransaction and Transaction.Commit/Transaction.Rollback methods.

Commands

Key EF Core CLI Commands

The primary commands are grouped under migrations, database, and dbcontext. 

Migrations Commands

These commands manage the lifecycle of database migrations. 

  • dotnet ef migrations add <NAME>: Adds a new migration. The <NAME> is an arbitrary name for the migration.

  • dotnet ef migrations list: Lists all available migrations in the project.

  • dotnet ef migrations remove: Removes the last migration. Use the --force (-f) option to remove the migration even if it has been applied to the database.

  • dotnet ef migrations script [FROM] [TO]: Generates a SQL script from migrations, or from the start (0) to a specified migration. The -i or --idempotent option can generate a script that works on a database at any migration.

  • dotnet ef migrations bundle: Creates a self-contained executable to apply migrations.

  • dotnet ef migrations has-pending-model-changes: Checks if any changes have been made to the model since the last migration. 

Database Commands

These commands interact directly with the database schema. 

  • dotnet ef database update [MIGRATION]: Updates the database to the last migration by default, or to a specific migration if <MIGRATION> is specified. Specifying '0' will revert all migrations.

  • dotnet ef database drop: Drops the database. Use the --force (-f) option to avoid a confirmation prompt. 

DbContext Commands

These commands manage the DbContext type and reverse engineer database schemas. 

  • dotnet ef dbcontext info: Gets information about a DbContext type.

  • dotnet ef dbcontext list: Lists available DbContext types in the project.

  • dotnet ef dbcontext scaffold <CONNECTION> <PROVIDER>: Generates a DbContext and entity type classes from an existing database schema.

  • dotnet ef dbcontext optimize: Generates a compiled version of the model for performance optimization

LINQ

Essential Operators

Select vs. SelectMany:

Select is used for simple projection (one-to-one), while SelectMany flattens sequences of sequences (one-to-many).

First() vs. FirstOrDefault()

First() throws an exception if the collection is empty, while FirstOrDefault() returns a default value (like null).

Any() vs. Count()

For existence checks, Any() is more efficient because it stops at the first match, whereas Count() must enumerate the entire collection.

Join vs. GroupJoin

Join is used for inner joins (one-to-one), while GroupJoin is used for one-to-many relationships, producing hierarchical results.

Performance & Best Practices

AsNoTracking()

In Entity Framework, use this for read-only queries to skip change-tracking overhead and improve speed.

Avoid N+1 Problems

Use .Include() and .ThenInclude() to eager-load related data and prevent multiple unnecessary database trips.

Project Early

Use .Select() to only fetch the specific fields you need instead of pulling entire database objects into memory.

Practical Coding Tasks

Find Second Highest:

var second = list.OrderByDescending(x => x).Skip(1).FirstOrDefault();.

Filter and Sort:

Find employees with a salary > 50k and name starting with "A", sorted by name.

Find Duplicates:

Use .GroupBy(x => x).Where(g => g.Count() > 1) to identify recurring items.

Left Outer Join:

Implement this using the into keyword combined with .DefaultIfEmpty().
