Angular 20 Features

Core features and performance

  • Stable Signals: Key signal-based APIs like effect, linkedSignal, and toSignal are now stable, offering a more powerful reactivity model.

  • Zoneless Change Detection: The experimental zoneless mode is now stable, allowing apps to run without Zone.js for improved performance and bundle size.

  • Incremental Hydration: Stable incremental hydration for Server-Side Rendering (SSR) makes apps faster by hydrating only necessary parts of the page on demand, boosting Core Web Vitals and SEO.

  • Modern Control Flow: The new, more modern syntax using @if, @for, and @switch blocks is now stable, simplifying templates and reducing boilerplate compared to older directives like *ngIf and *ngFor. 

Exception Handling

1. Global Error Handling (ErrorHandler) 

Angular provides a built-in ErrorHandler service that acts as a central catch-all for uncaught synchronous errors anywhere in the application. This is ideal for logging errors to an external service or displaying a generic error notification to the user. 

  • How to use: Create a custom class that implements the ErrorHandler interface and override the handleError method. Then, provide this custom handler in your main application module or configuration. 

import { ErrorHandler, Injectable } from '@angular/core';

@Injectable()

export class GlobalErrorHandlerService implements ErrorHandler {

handleError(error: any): void {

// Custom logic for handling errors (e.g., logging to a server, showing a generic message)

console.error('An unhandled error occurred:', error);

// You can inject other services here (e.g., a logging service or a notification service)

}

}

  • Provide the service (in app.module.ts or app.config.ts for standalone apps):

// app.module.ts (or app.config.ts providers array)

import { ErrorHandler, Provider } from '@angular/core';
import { GlobalErrorHandlerService } from './global-error-handler.service';
// ... other imports
export const providers: Provider[] = [
// ... other providers
{ provide: ErrorHandler, useClass: GlobalErrorHandlerService }
];
2. Handling HTTP Errors (HttpInterceptor)

For errors that occur during HTTP requests, such as 404 Not Found or 500 Internal Server errors, the best approach is to use an HttpInterceptor. Interceptors can globally catch and handle HTTP error responses. 

  • How to use: Create an injectable class that implements HttpInterceptor and use the catchError RxJS operator. 

To provide the interceptor, include it in your module's providers array. You can find example code for creating and providing an HttpErrorInterceptor in the referenced documents. 

3. Local Error Handling (RxJS catchError)

For handling errors from specific asynchronous operations like individual HTTP calls, where you need localized error handling, use the catchError RxJS operator within the service or component consuming the observable. This allows for displaying specific messages or retrying operations. Refer to the source documents for an example of using catchError in a data service. 

4. Component-Level Error Handling (try-catch blocks)

Standard JavaScript try...catch blocks are suitable for handling synchronous code within components or services. See the original response or the referenced document for an example of implementing a try...catch block in a component method. 

Types of Forms

1. Reactive Forms (Model-Driven)

Reactive forms are a model-driven approach where the form logic and structure are defined primarily within the component class using programmatic means. This method offers greater control and is ideal for complex forms, dynamic scenarios, and forms requiring extensive testing

2. Template-Driven Forms (Template-First)

Template-driven forms are an easier, template-first approach where the form logic and controls are managed predominantly within the HTML template using directives. They are simpler to set up and are best for basic forms like login pages or contact forms with minimal validation.

Pipes

  • Built-in Pipes: Angular provides a variety of pre-built pipes for common data transformations. Examples include:

    • DatePipe: Formats date values (e.g., {{ today | date }}).

    • UpperCasePipe and LowerCasePipe: Convert text to uppercase or lowercase.

    • CurrencyPipe and PercentPipe: Format numbers as currency or percentages based on locale rules.

    • AsyncPipe: Automatically subscribes to a Promise or Observable and returns the latest value.

    • JsonPipe: Converts a JavaScript object to a JSON formatted string, useful for debugging.

  • Custom Pipes: Developers can create their own pipes for specific, unique data transformations not covered by built-in pipes. Custom pipes are defined using the @Pipe decorator and implement the PipeTransform interface.

Custom pipe?

Apart from built-in pipes, you can write your own custom pipe with the below key characteristics:

  1. A pipe is a class decorated with pipe metadata @Pipe decorator, which you import from the core Angular library For example,

@Pipe({name: 'myCustomPipe'})

  1. The pipe class implements the PipeTransform interface's transform method that accepts an input value followed by optional parameters and returns the transformed value. The structure of PipeTransform would be as below,

  2. interface PipeTransform {

  3. transform(value: any, ...args: any[]): any

}

  1. The @Pipe decorator allows you to define the pipe name that you'll use within template expressions. It must be a valid JavaScript identifier.

template: `{{someInputValue | myCustomPipe: someOtherValue}}` 

Interceptor

In Angular, HTTP interceptors are a powerful middleware mechanism that allows you to inspect and transform HTTP requests and responses globally, from a central location. They act as a layer between your application's HttpClient service and the backend server. 

Why Use Interceptors?

Interceptors help centralize logic for "cross-cutting concerns," avoiding repetitive code in every service or component that makes an HTTP call. Common use cases include: 

  • Authentication: Automatically attach authentication tokens (e.g., JWT) to the headers of every outgoing request.

  • Error Handling: Catch and handle errors from HTTP responses globally (e.g., displaying a user-friendly notification for a 404 or 500 error).

  • Logging/Monitoring: Log request and response details (like URL, method, and response time) for debugging and performance monitoring.

  • Caching: Implement caching strategies to store responses and serve them for subsequent requests, improving performance.

  • Request/Response Transformation: Modify the structure of request bodies or response data (e.g., converting an API response format).

What is a template?

A template is a HTML view where you can display data by binding controls to properties of an Angular component. You can store your component's template in one of two places. You can define it inline using the template property, or you can define the template in a separate HTML file and link to it in the component metadata using the @Component decorator's templateUrl property.

What is a module?

Modules are logical boundaries in your application and the application is divided into separate modules to separate the functionality of your application. Lets take an example of app.module.ts root module declared with @NgModule decorator.

The NgModule decorator has five important (among all) options:

  1. The imports option is used to import other dependent modules. The BrowserModule is required by default for any web based angular application.

  2. The declarations option is used to define components in the respective module.

  3. The bootstrap option tells Angular which Component to bootstrap in the application.

  4. The providers option is used to configure a set of injectable objects that are available in the injector of this module.

  5. The entryComponents option is a set of components dynamically loaded into the view.

Component in Angular

In Angular, components are the main building blocks of an application's user interface. Fundamentally, all Angular components share a core structure, but they can be categorized based on their relationship within the application's hierarchy and how they manage dependencies. 

Core Component Structure

Every Angular component consists of three main parts: 

  • A TypeScript class: This contains the component's logic, handles user input, and fetches data.

  • An HTML template: This defines the component's view or user interface.

  • A CSS selector: This is a custom HTML tag (e.g., <app-root>) that tells Angular where to insert the component's instance into the DOM.

  • Optionally, CSS styles: These styles are typically scoped only to the component's own template. 

Types of Components by Application Hierarchy

Within an application, components primarily function in one of two roles in relation to one another: 

  • Parent Components: These components contain and manage other components (child components). They often pass data to children using @Input() properties and listen for events from children using @Output() properties.

  • Child Components: These are nested within parent components and typically focus on a specific piece of UI or functionality. They communicate with their parent components to share data and events.

Angular application goes through an entire set of processes or has a lifecycle right from its initiation to the end of the application. The representation of lifecycle in pictorial representation as follows,

The description of each lifecycle method is as below,

  2. ngOnInit: This is called whenever the initialization of the directive/component after Angular first displays the data-bound properties happens.

  3. ngDoCheck: This is for the detection and to act on changes that Angular can't or won't detect on its own.

  5. ngAfterContentChecked: This is called in response after Angular checks the content projected into the component.

  6. ngAfterViewInit: This is called in response after Angular initializes the component's views and child views.

  7. ngAfterViewChecked: This is called in response after Angular checks the component's views and child views.

  8. ngOnDestroy: This is the cleanup phase just before Angular destroys the directive/component.

What is a data binding?

Data binding is a core concept in Angular and allows to define communication between a component and the DOM, making it very easy to define interactive applications without worrying about pushing and pulling data. There are four forms of data binding(divided as 3 categories) which differ in the way the data is flowing.

  1. From the Component to the DOM:

Interpolation: {{ value }}: Adds the value of a property from the component

<li>Name: {{ user.name }}</li>

<li>Address: {{ user.address }}</li>

Property binding: [property]=”value”: The value is passed from the component to the specified property or simple HTML attribute

<input type="email" [value]="user.email">

  1. From the DOM to the Component: Event binding: (event)=”function”: When a specific DOM event happens (eg.: click, change, keyup), call the specified method in the component

<button (click)="logout()"></button>

  1. Two-way binding: Two-way data binding: [(ngModel)]=”value”: Two-way data binding allows to have the data flow both ways. For example, in the below code snippet, both the email DOM input and component email property are in sync

<input type="email" [(ngModel)]="user.email">

What is a service?

A service is used when a common functionality needs to be provided to various modules. Services allow for greater separation of concerns for your application and better modularity by allowing you to extract common functionality out of components.

Let's create a repoService which can be used across components,

import { Injectable } from '@angular/core';

import { Http } from '@angular/http';

@Injectable({ // The Injectable decorator is required for dependency injection to work

// providedIn option registers the service with a specific NgModule

providedIn: 'root', // This declares the service with the root app (AppModule)

})

export class RepoService{

constructor(private http: Http){

}

fetchAll(){

return this.http.get('https://api.github.com/repositories');

}

}

The above service uses Http service as a dependency.

Lazy loading?

Lazy loading is one of the most useful concepts of Angular Routing. It helps us to download the web pages in chunks instead of downloading everything in a big bundle. It is used for lazy loading by asynchronously loading the feature module for routing whenever required using the property loadChildren. Let's load both Customer and Order feature modules lazily as below,

const routes: Routes = [
{
path: 'customers',
loadChildren: () => import('./customers/customers.module').then(module => module.CustomersModule)
},
{
path: 'orders',
loadChildren: () => import('./orders/orders.module').then(module => module.OrdersModule)
},
{
path: '',
redirectTo: '',
pathMatch: 'full'
}
];

State management

State Management is a term that defines a way we can store data, modify it, and react to its changes. In our case, the libraries NGRX and NGXS are using a pattern called CQRS (Command Query Responsibility Segregation).

It states that every method should either be a command that performs an action, or a query that returns data to the caller, but not both.

State Management acts as a single source of truth for your application.

You can build an app without complex State Management. You can use only services, and you're good to go. Adding a State Management library (e.g NGRX/NGXS) to your application would add some complexity and boilerplate, but then you'll have the benefits of (quoted from https://stackoverflow.com/a/8820998/1860540):

  1. Large team - You can split development tasks between people easily if you have chosen CQRS architecture. Your top people can work on domain logic leaving regular stuff to less skilled developers. 2. Difficult business logic - CQRS forces you to avoid mixing domain logic and infrastructural operations. 3. Scalability matters - With CQRS you can achieve great read and write performance, command handling can be scaled out on multiple nodes and as queries are read-only operations they can be optimized to do fast read operations.

AuthGuards

AuthGuards in Angular (including Angular 20) are functional, injectable services used to protect routes from unauthorized access by implementing canActivate or canMatch functions. They are essential for checking authentication status or user roles, often redirecting users to a login page if they are not authorized. In modern Angular, these are best implemented as functional guards using inject() for clean, reactive logic. 

Key Concepts for AuthGuards in Angular 20

  • Functional Approach: Modern Angular (v17+) prefers functional guards (CanActivateFn) over class-based guards for simplicity and tree-shaking efficiency.

  • canActivate: Determines if a route can be activated.

  • canMatch: Determines if a route can be matched at all, useful for lazy loading.

  • Signals & httpResource(): Angular 20 increasingly leverages Signals for reactive UI updates and httpResource() for managing asynchronous authentication state. 

Implementation Steps

  1. Generate a Guard: Use the Angular CLI to generate a new functional guard:

bash

ng generate guard auth

Share Data Between Component

Child to Parent Communication

Use the @Output() decorator with an EventEmitter in the child component to emit events (with data) that the parent component listens to. 

  • In the child component (child.component.ts):

typescript

import { Component, Output, EventEmitter } from '@angular/core';
@Component({
selector: 'app-child',
template: `<button (click)="addNewItem(value)">Add Item</button>`
})
export class ChildComponent {
@Output() newItemEvent = new EventEmitter<string>();
addNewItem(value: string) {
this.newItemEvent.emit(value); // Emit the data as an event
}
}

  • In the parent component's template (parent.component.html):

html

<app-child (newItemEvent)="addItem($event)"></app-child>
<ul>
<li *ngFor="let item of items">{{ item }}</li>
</ul>

  • In the parent component (parent.component.ts):

typescript

import { Component } from '@angular/core';
@Component({ ... })
export class ParentComponent {
items = ['item1', 'item2'];
addItem(newItem: string) {
this.items.push(newItem); // Method to handle the event data
}
}

 

3. Communication Between Unrelated Components (Siblings, Grandchildren, etc.)

A shared service using RxJS Subject or BehaviorSubject is the standard and most robust method for components without a direct hierarchical relationship. 

  • Create a shared service (data.service.ts):

typescript

import { Injectable } from '@angular/core';
import { BehaviorSubject, Observable } from 'rxjs';
@Injectable({
providedIn: 'root' // Makes the service a singleton
})
export class DataService {
private dataSubject = new BehaviorSubject<string>('Default Data');
currentData$: Observable<string> = this.dataSubject.asObservable();
changeData(data: string) {
this.dataSubject.next(data); // Update the data value
}
}

  • In any component that needs to send data:
    Inject the service and call changeData().

typescript

// sender.component.ts

import { Component } from '@angular/core';
import { DataService } from './data.service';
@Component({ ... })
export class SenderComponent {
constructor(private dataService: DataService) {}
sendData() {
this.dataService.changeData('New Data Value');
}
}

  • In any component that needs to receive data:
    Inject the service and subscribe to the observable.

typescript

// receiver.component.ts

import { Component, OnInit } from '@angular/core';
import { DataService } from './data.service';
@Component({ ... })
export class ReceiverComponent implements OnInit {
receivedData: string;
constructor(private dataService: DataService) {}
ngOnInit() {
this.dataService.currentData$.subscribe(data => {
this.receivedData = data; // Update local property when data changes
});
}
}

Observable & Promise

Both Promises and Observables handle asynchronous operations in JavaScript, but they serve entirely different use cases. In short: Promises deliver a single future value, while Observables represent a stream of values over time. [1]

Here is a quick breakdown of their core differences:

Feature Promise Observable
Value Count Emits exactly one value (then completes). Emits multiple values over time (acts as a stream).
Execution Timing Eager: Starts executing immediately upon creation. Lazy: Only executes when someone subscribes to it.
Cancellation Cannot be canceled. Can be canceled by unsubscribing.
Composition Uses .then() and .catch(). Provides RxJS operators like .pipe(), .map(), .filter().

When to Use Which?

  • Use Promises for: One-time, standalone asynchronous operations like fetching app configuration or completing a basic HTTP POST request.

  • Use Observables for: Continuous, event-driven data—such as WebSockets, DOM events (clicks, keystrokes), or handling multiple HTTP responses over
